## Context

Users found SLYE's rewrite too literal when the source is not heavy jargon: it often came back nearly identical. The user asked for a second, full rewrite next to the existing lighter one, switchable with clickable tabs, first based on the MIT-licensed [unslop](https://github.com/cursor/plugins/blob/main/pstack/skills/unslop/SKILL.md) skill. A Pi 1.3.0 spike showed that an entry renderer wrapped in `MouseRegion` receives clicks in fullscreen mode, that regular mode leaves the mouse to the terminal, and that an extension shortcut plus a status update re-renders the card in both modes. OMP routes inline clicks only to its own subagent cards. Work is tracked in [TASK-21](../tasks/task-21%20-%20Add-Rewrite-and-Simple-tabs-to-the-SLYE-companion-card-on-Pi.md).

In live use on 2026-10-21 the unslop-based prompt did worse than the light rewrite on Italian corporate jargon: it kept English business terms and sometimes returned the target unchanged. Its rules to preserve the language mix and every term protected the jargon, and it no longer told the model to replace corporate jargon. The user clarified the goal: a version a reader with ADHD can follow, linear, coherent, and short, as described by the MIT-licensed [i-have-adhd](https://github.com/ayghri/i-have-adhd) skill.

## Decision

On Pi, make two parallel completions per rewrite with the same model: Light with the selected prompt and ELI5 with a built-in prompt adapted from unslop and i-have-adhd. A first ELI5 prompt that only allowed reordering still mirrored the target's paragraphs and headings in live use, so the ELI5 prompt tells the model to write a new text from scratch in a fixed order: bottom line, done, steps, key facts, open decisions, side notes, with labels in the target's language. It keeps every fact, completed action, and decision and aims for about half the length. In live use that version still kept workplace jargon and acronyms (KPI, stakeholder, RACI), so ELI5 also uses words a smart 12-year-old knows and keeps unchanged only what the reader must type or recognise exactly; Light still preserves the target's wording more closely. A structure reminder at the end of the ELI5 request stops fast models from mirroring one-paragraph targets. It treats business English inside a non-English target as jargon rather than an intentional language mix. Append one immutable companion holding both texts only when both succeed, because a companion cannot be updated later and a half card could never be completed. Keep the Light text in the existing `display` field and the ELI5 text in a new `rewrite` field, so old cards, OMP, and duplicate detection keep working.

Name the tabs ELI5 and Light, ELI5 first. "Rewrite"/"Simple" and "Easy"/"Simple" were rejected because the names did not convey the difference between a reorganized explanation and a light touch-up. Select a tab by clicking (fullscreen) or with `ctrl+\` (all modes); `alt+s` was rejected because iTerm2 with Option set to Normal does not send it. Keep one in-memory active tab for all cards, unpersisted, rather than per-card state that a shortcut could not target. A custom `slye-prompt.md` replaces only the Light prompt.

Render the Pi card with the theme's `customMessageBg` at half saturation instead of a fixed color, so light and dark themes both stay readable while avoiding Pi 1.0's saturated default violet. A rounded border was rejected because its side characters end up in copied text.

Leave OMP unchanged for now: one Light completion, no tabs, no shortcut. Stacking both versions on OMP was rejected as visually poor. Keep the tab UI in its own module and reach its mouse and color helpers through a namespace import: OMP's TUI library lacks them, and a named import of a missing member would stop OMP from loading SLYE. Support only the current Pi release; older Pi hosts are out of scope.

## Consequences

Each Pi rewrite costs about twice as much as before, automatic rewrites included, and its latency is that of the slower completion. A failure of either completion discards the other. Mouse selection works only in Pi fullscreen mode; the shortcut is the portable path, and its re-render relies on a status update because Pi gives shortcut handlers no render request. ELI5 may change the target's Markdown structure and order, and its quality depends on the model: in the 2026-10-21 prompt trials one model dropped a fact from a long answer, and a fast model reordered less than larger ones. Both tabs use one configured model; a separate ELI5 model was deferred because the card waits for the slower completion anyway and per-tab models would change the configuration contract and every command that rewrites it. In the 2026-10-21 trials ELI5 quality varied by model (see the specification's benchmark guidance). If the Light tab turns out to be unused, it can be removed in a later change.
